## 1. Просроченные заказы

### Что нужно
- Счётчик просроченных заказов на дашборде (как в RO App: «50 tickets Overdue»)
- Красная подсветка строк в таблице, у которых `deadline < NOW()` и статус не финальный
- Фильтр по просроченным (`GET /orders?overdue=true`)

### Бэкенд
- `GET /orders` — добавить параметр `overdue` (boolean)
  - Если `true`: `WHERE o.deadline < NOW() AND os.is_final = FALSE`
- В ответ добавить вычисляемое поле `is_overdue: boolean`

### Фронтенд
- `DashboardPage`:
  - Добавить карточку «Просрочено» в `statCards`
  - В таблице: красный фон строки при `is_overdue === true`
  - Вкладка «Просроченные» в `tabs`

### Файлы
- `backend/src/routes/orders.ts` — параметр `overdue` в GET /
- `frontend/src/pages/DashboardPage.tsx` — карточка + подсветка + вкладка
- `frontend/src/api.ts` — поле `is_overdue` в типе `Order`

## 2. Фильтр «Мои заказы»

### Что нужно
- На дашборде счётчик «Мои заказы» (заказы, назначенные на текущего пользователя)
- Быстрое переключение на заказы текущего мастера

### Бэкенд
- `GET /orders` — уже есть параметр `master_id`

### Фронтенд
- `DashboardPage`:

  - При клике — запрос `getOrders({ master_id: user.id })`

### Файлы
- `frontend/src/pages/DashboardPage.tsx` — логика вкладки/фильтра
- `frontend/src/context/AuthContext.tsx` — убедиться, что `user.id` доступен

## 3. Уведомления клиентов через Telegram

### Что нужно
- Автоматическая отправка сообщения клиенту при смене статуса заказа
- Клиент должен быть привязан к Telegram (поле `telegram_id` или `chat_id`)

### Бэкенд
- Сервис `telegram.ts` уже существует — нужно подключить к смене статуса
- `PATCH /orders/:id/status` — после смены статуса:
  - Если у клиента есть `telegram_chat_id` — отправить уведомление
  - Шаблон сообщения: «Статус заказа №{id} изменён на "{status_name}"»
- Миграция: добавить поле `telegram_chat_id` в таблицу `clients`
- `PATCH /clients/:id` — возможность сохранить `telegram_chat_id`
- `POST /auth/telegram-link` — эндпоинт для привязки Telegram (опционально)

### Фронтенд
- В карточке клиента (OrderDetailPage) — поле Telegram ID
- Инструкция для клиента: как привязать Telegram

### Файлы
- `backend/src/routes/orders.ts` — вызов `sendTelegramMessage` при смене статуса
- `backend/src/services/telegram.ts` — шаблоны сообщений
- `backend/migrations/` — миграция `telegram_chat_id`
- `frontend/src/pages/OrderDetailPage.tsx` — поле telegram

## 4. Экспорт отчётов в Excel/CSV

### Что нужно
- Кнопка «Экспорт» на странице финансов и на дашборде заказов
- Скачивание `.csv` или `.xlsx` файла

### Бэкенд
- `GET /finance/report/export?from=...&to=...` — возвращает CSV
- `GET /orders/export?status=...&master_id=...` — возвращает CSV списка заказов
- Формат: CSV с заголовками, разделитель `;` (для Excel в русской локали)

### Фронтенд
- Кнопка «Экспорт в Excel» на `FinancePage`
- Кнопка «Экспорт» на `DashboardPage`
- Скачивание через blob + `URL.createObjectURL`

### Файлы
- `backend/src/routes/finance.ts` — эндпоинт `/export`
- `backend/src/routes/orders.ts` — эндпоинт `/export`
- `frontend/src/pages/FinancePage.tsx` — кнопка экспорта
- `frontend/src/pages/DashboardPage.tsx` — кнопка экспорта

## 5. Группировка заказов (Group)

### Что нужно
- Возможность объединять заказы в группы (например, «iPhone 14 — партия 1»)
- Поле `group_name` или `group_id` в заказе
- Фильтр по группе в таблице

### Бэкенд
- Миграция: таблица `order_groups` (id, name, created_at)
- Миграция: поле `group_id INT REFERENCES order_groups(id)` в `orders`
- `GET /orders` — параметр `group_id`
- `POST /order-groups` — создать группу
- `GET /order-groups` — список групп
- `PATCH /orders/:id` — возможность изменить `group_id`

### Фронтенд
- Выпадающий список «Группа» в фильтрах таблицы
- Возможность назначить группу при создании/редактировании заказа

### Файлы
- `backend/migrations/` — новые таблица и поле
- `backend/src/routes/orders.ts` — параметр `group_id`, PATCH group_id
- `backend/src/routes/order-groups.ts` — новый роутер (или добавить в settings)
- `frontend/src/pages/DashboardPage.tsx` — фильтр
- `frontend/src/pages/CreateOrderPage.tsx` — поле группы
- `frontend/src/pages/OrderDetailPage.tsx` — редактирование группы

## 9. Запчасти на форме создания ✅

### Что сделано
- Вкладка **«Запчасти и услуги»** на форме создания заказа
- Выбор запчасти из выпадающего списка (с остатками)
- Таблица добавленных запчастей: название, артикул, цена, количество, сумма
- Возможность изменить количество или удалить запчасть
- При создании заказа запчасти списываются со склада (в транзакции)
- Бэкенд принимает `parts: [{ part_id, quantity }]`

### Файлы
- `frontend/src/pages/CreateOrderPage.tsx` — вкладка parts
- `frontend/src/api.ts` — `parts` в `CreateOrderInput`
- `backend/src/routes/orders.ts` — обработка `parts[]` в POST /orders
