### 3. Добавить `requireAuth` на роут `/users` (уже есть, но проверить)

**Где:** `backend/src/routes/users.ts`

  // ...

### 4. Перенести JWT из localStorage в httpOnly cookie

**Где:** `frontend/src/context/AuthContext.tsx` и `backend/src/routes/auth.ts`

**Что изменить:**

#### 4.1. Backend — при логине устанавливать httpOnly cookie

В `backend/src/routes/auth.ts` после успешного логина, помимо JSON-ответа, установить cookie:

```ts
import cookieParser from 'cookie-parser';

// В app.ts
app.use(cookieParser());

// В auth.ts — при логине
res.cookie('token', token, {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'strict',
  maxAge: 24 * 60 * 60 * 1000 // 24 часа
});
```

**Добавить в package.json:** `cookie-parser` и `@types/cookie-parser`.

#### 4.2. Frontend — не хранить токен в localStorage

- Удалить `localStorage.setItem('token', ...)` и `localStorage.getItem('token')`
- Токен будет автоматически отправляться с httpOnly cookie
- API-запросы не будут вручную добавлять `Authorization: Bearer ...`
- При logout — очищать cookie (вызвать `POST /auth/logout`)
- Добавить эндпоинт `POST /auth/logout` на бэкенде, который очищает cookie

**Внимание:** Это ломает текущую архитектуру `api.ts`, где токен читается из localStorage и добавляется в заголовок. Потребуется рефакторинг `api.ts`.

**Альтернатива (проще):** Оставить Bearer-схему, но:
- Использовать `sessionStorage` вместо `localStorage` (токен живёт пока открыта вкладка)
- Добавить флаг при логине: `httpOnly` куки **в дополнение** к Bearer для защиты от XSS

### 6. Скрыть детали ошибок в production

**Где:** `backend/src/app.ts`, обработчик ошибок

**Сейчас:**
```ts
const message = error instanceof Error ? error.message : 'Неизвестная ошибка сервера';

```

**Надо:**
```ts
if (process.env.NODE_ENV === 'production') {
  res.status(500).json({ error: 'Внутренняя ошибка сервера' });

  const message = error instanceof Error ? error.message : 'Неизвестная ошибка сервера';
  res.status(500).json({ error: message });
}
```

### 8. Усилить валидацию скидки и стоимости

**Где:** `backend/src/routes/orders.ts`

**Сейчас (схема обновления заказа):**
```ts
const updateOrderSchema = z.object({
  cost: z.number().nonnegative().optional(),
  discount: z.number().nonnegative().optional(),
  // ...
});
```

**Надо:** Добавить проверку в обработчик `PATCH /:id`:

```ts
if (input.discount !== undefined && input.cost !== undefined && input.discount > input.cost) {
  throw new BadRequestError('Скидка не может превышать стоимость');
}
if (input.discount !== undefined && order.rows[0].cost !== undefined) {
  // Если cost не меняется, проверяем с текущим значением
  const currentCost = input.cost ?? order.rows[0].cost;
  if (input.discount > currentCost) {
    throw new BadRequestError('Скидка не может превышать стоимость');
  }
}
```

То же самое для `POST /orders` — проверять `discount <= estimated_cost`.

### 10. Добавить `ON DELETE RESTRICT` на внешние ключи

**Где:** Миграции БД (`backend/migrations/`)

Для `payment_methods` и `expense_categories`, на которые ссылаются `payments` и `expenses`, изменить внешние ключи с каскадного на restrict.

**Решение через код:** В `DELETE`-эндпоинтах settings добавить проверку, что нет связанных записей перед удалением.

```ts
// Пример для payment-methods
settingsRouter.delete('/payment-methods/:id', async (req, res, next) => {
  try {
    const { id } = req.params;
    // Проверяем, есть ли платежи с этим способом
    const usage = await pool.query(
      'SELECT COUNT(*)::int AS cnt FROM payments WHERE payment_method_id = $1',
      [id]
    );
    if (usage.rows[0].cnt > 0) {
      throw new BadRequestError(
        'Нельзя удалить способ оплаты, по которому есть платежи'
      );
    }
    await pool.query('DELETE FROM payment_methods WHERE id = $1', [id]);
    res.json({ message: 'Удалено' });
  } catch (error) {
    next(error);
  }
});
```
